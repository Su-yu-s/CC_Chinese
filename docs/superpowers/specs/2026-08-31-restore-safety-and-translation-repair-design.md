# 恢复安全、五项翻译与补丁可靠性修复设计

## 状态

- 日期：2026-08-31
- 范围：CC_Chinese 安装、备份、恢复、检测、权限、GUI 生命周期及五项侧栏翻译
- 用户已确认：采用“隔离不兼容旧备份并拒绝恢复”的安全策略

## 背景与已确认事实

当前实现存在 11 项已复验缺陷，其中恢复链会在缺少版本与来源校验时修改官方文件。现存 `json-only` 与 `chunks` 目录跨多个日期累计文件，`patch-state.json` 指向的安装路径已经不存在，但检测器仍将备份显示为“已准备”。因此旧扁平备份不能被视为可信的当前版本快照。

新版 Claude 侧栏已经由旧式 `label:"<name>"` 字面量迁移到 React-Intl 消息目录。当前中文目录中的侧栏值为“新 / 项目 / 作品 / 已安排 / 自定义”，所以修改 bundle 的英文 `defaultMessage` 或旧式 `label` 不会覆盖按消息 ID 返回的中文。截图中的失败现象与这一数据流一致。

## 目标

1. 恢复操作不得删除或改写官方原生 `zh-CN` 白名单。
2. 不允许跨安装、跨包版本或跨资源布局恢复备份。
3. 工具自身的状态文件不得进入 Claude 资源目录。
4. 五项侧栏文案稳定显示为“新建 / 项目 / 作品 / 定时 / 定制”。
5. 安装和恢复必须由真实检测结果决定成功状态。
6. v1、v2 等多个 assets 目录必须分别备份并恢复到原路径。
7. 用户原有 locale 与字体配置必须精确恢复。
8. 任一必要备份失败时不得继续修改对应文件或宣告成功。
9. WindowsApps 权限处理不得递归接管整个 resources 树。
10. 汉化或恢复期间关闭窗口不得终止正在写文件的进程。
11. “备份已准备”必须表示存在与当前安装严格匹配且完整的快照。

## 非目标

- 不自动修复来源不明、已经被其他工具修改或与当前版本不匹配的 Claude 安装。
- 不自动删除现有旧扁平备份。
- 不把用户聊天、项目、工作区或 Claude 业务数据纳入备份。
- 不通过全局替换单字“新”或通用词“自定义”修复侧栏。
- 本轮不增加联网恢复、下载官方包或依赖第三方备份服务。

## 方案选择

采用带 manifest 的事务式快照。仅按版本号分目录不能识别同版本热更新或文件漂移；完全依赖反向字符串替换又无法精确还原官方 JSON、用户配置和未知 bundle 变化。因此二者均不能满足恢复安全要求。

## 1. 安装身份与快照结构

### 1.1 安装身份

每个快照绑定一个稳定的安装身份，包含：

- 规范化后的 `app_dir`；
- WindowsApps 包目录名称或本地安装版本信息；
- 未被 CC_Chinese 修改的可执行文件或 `app.asar` 指纹（存在时）；
- assets 版本目录名称与所有 JS 相对文件名的确定性指纹。

最后一项只使用文件路径集合，不使用补丁后会变化的内容或大小，因此同一次安装在汉化后仍能得到相同身份；Claude 更新、资源重排或 bundle 文件名变化会产生不同身份。

### 1.2 目录布局

新快照存放在：

```text
Claude-zh-CN-official-backup/
  snapshots/
    <install-id>/
      manifest.json
      payload/
        resources/
          en-US.json
          ion-dist/assets/v1/index-<bundle-name>.js
          ion-dist/assets/v2/index-<bundle-name>.js
```

payload 中的每个文件均相对于 `app/resources` 保存完整路径。chunk 备份不再以单个 assets 目录为根，因此 v1/v2 同名文件不会覆盖。

### 1.3 Manifest

`manifest.json` 至少包含：

- schema 版本；
- install-id 与完整安装身份字段；
- 创建时间与补丁版本；
- 快照状态：`staging`、`complete` 或 `invalid`；
- 每个文件的 resources 相对路径；
- 原文件是否存在；
- 原文件 SHA-256；
- payload 文件 SHA-256；
- 补丁完成后的预期 SHA-256；
- 原始 locale 键是否存在及其 JSON 值；
- 原始字体配置键是否存在及其 JSON 值；
- 原始配置文件路径；
- 本次创建、修改和注入的操作清单。

Manifest 元数据与 payload 分离。恢复只遍历 manifest 的文件清单，绝不递归复制快照根目录。

## 2. 旧备份隔离策略

现有 `json-only`、`chunks` 和旧版 `Claude_*` 扁平备份保持原位置，不删除、不改写、不尝试迁移。没有新 manifest 的备份统一判定为 `legacy_incompatible`。

行为固定如下：

- 检测页显示“备份不兼容”，不能显示“已准备”；
- 点击恢复时，在修改任何目标前返回明确错误；
- 错误信息提示通过 Claude 官方修复或重装获得干净安装，然后重新运行 CC_Chinese；
- 不提供“仍然继续”开关，避免把高风险选择重新交给普通确认框；
- 旧文件仅保留给人工取证，不参与自动恢复。

## 3. 事务式安装

### 3.1 预检与计划

安装器首先生成完整 mutation plan，列出：

- 三份中文 JSON 目标；
- 英文回退资源；
- 实际包含语言目录或硬编码文案的入口/shared bundle；
- 所有待注入或更新运行时的 index bundle；
- locale 与字体配置目标。

在任何写入前完成：安装身份计算、旧快照兼容性判断、目标可读性检查、精确权限准备及原始文件快照。

### 3.2 备份门禁

对于原本存在的每个目标文件，必须成功复制到 staging payload 并核对 SHA-256。原本不存在的目标只在 manifest 中记录 `existed=false`。任何必要备份或哈希校验失败时：

- 快照标记为 `invalid`；
- 安装立即失败；
- 零目标文件被修改；
- GUI 显示失败目标与原因。

重复汉化同一 install-id 时复用首次 `complete` 快照，不覆盖最初的官方基线，不覆盖 locale 原值。

### 3.3 原子写入与提交

所有 JSON、JS、配置和状态写入统一使用共享原子写接口：

1. 在目标同目录创建唯一临时文件；
2. 写入完整内容并刷新缓冲区；
3. 复制必要权限与属性；
4. 使用 `os.replace` 原子替换；
5. 失败时删除临时文件，原目标保持不变。

每次文件修改后记录补丁后 SHA-256。全部步骤及安装后检测通过后，manifest 才从 `staging` 切换为 `complete`。若中途失败或最终检测失败，安装器使用 staging 中的原文件回滚已修改目标，并恢复配置原值。

## 4. 安全恢复

恢复分为预检与提交两阶段。

### 4.1 恢复预检

恢复必须一次性验证：

- 当前安装身份与 manifest 完全一致；
- manifest 状态为 `complete`；
- 所有 `existed=true` 的 payload 文件存在且哈希匹配；
- 当前目标文件仍是 manifest 记录的补丁后版本，或已处于原始版本；
- locale 配置路径与记录一致；
- 没有路径逃逸、绝对路径或 `..` 路径。

任一条件不满足时零写入并拒绝恢复。已经处于原始版本的文件视为幂等成功，不再覆盖。

### 4.2 恢复提交

- `existed=true`：从 payload 原子恢复到 manifest 记录的完整 resources 相对路径；
- `existed=false`：仅当当前文件哈希等于本工具记录的补丁后哈希时删除；
- locale 与字体配置：原键存在则恢复原 JSON 值，原键不存在才删除；
- 注入运行时和静态替换由原文件恢复完成，不再对全部 bundle 做猜测式反向替换；
- 恢复不执行 `content.replace(',"zh-CN"', '')`；
- 恢复不硬编码 `assets/v1`；
- 恢复不复制 `patch-state.json`、`chunk-state.json` 或任何未列入 manifest 的文件。

提交前暂存当前补丁文件，以便恢复阶段发生意外时回滚到恢复前状态。全部恢复成功后删除或失效当前安装的补丁状态缓存，但保留官方基线快照供幂等验证。

## 5. 五项侧栏翻译

### 5.1 React-Intl 消息目录

直接修改 `core/resources/frontend-zh-CN.json` 中以下侧栏专用消息：

| 消息 ID | 当前值 | 目标值 |
|---|---|---|
| `bW7B87wFFp` | 新 | 新建 |
| `UxTJRaKagI` | 项目 | 项目 |
| `eW5eoWkxy3` | 作品 | 作品 |
| `cXAlMRerxW` | 已安排 | 定时 |
| `TXpOBiuxud` | 自定义 | 定制 |

只修改这些 ID。其他同值消息，例如 Cowork 新功能徽章中的“新”，保持不变。

### 5.2 静态兼容规则

保留旧版精确 `label:"<name>"` 规则，并增加：

- `artifactLabel="Artifacts"` → `artifactLabel="作品"`；
- `artifactLabel="工件"` → `artifactLabel="作品"`。

反向恢复映射继续由精确替换表自动生成。路径 `Documents/Claude/Artifacts`、用户项目名、品牌名、SVG 和普通业务文本不参与替换。

### 5.3 动态界面兜底

DOM 运行时增加独立的侧栏上下文映射：

- `New`、`新` → `新建`；
- `Projects` → `项目`；
- `Artifacts`、`工件` → `作品`；
- `Scheduled`、`已安排` → `定时`；
- `Customize`、`自定义` → `定制`。

该映射只在 `nav/aside/[role=navigation]` 内具有链接、按钮、菜单项或侧栏路由信号的节点上生效。不得把“新”或“自定义”加入全局文本映射。

## 6. 安装后检测与 GUI 状态

`installer.run_install()` 在返回成功前调用 `detector.build_status(app_dir=current_app_dir)`。成功条件同时要求：

- 三份目标中文资源存在且与打包资源一致；
- 当前 install-id 存在完整、匹配的 manifest；
- 运行时补丁标记存在于当前入口 bundle；
- 当前补丁状态引用的文件属于当前安装。

检测失败时安装器回滚并返回失败。`MainWindow._on_action_done()` 不再直接设置 `localized=True` 或“已汉化”，安装和恢复结束后统一触发异步重检，最终 UI 只接受检测器结果。

## 7. 精确权限处理

权限准备提升到 installer 总入口，并且每次安装或恢复只执行一次。`patch_json` 与 `patch_chunks` 不再各自递归处理 `resources`。

WindowsApps 下只对 mutation plan 中已存在的目标文件以及需要创建目标的父目录执行权限操作：

- 不使用针对整个 resources 的 `takeown /r`；
- 不使用针对整个 resources 的 `icacls /t`；
- 命令采用单目标短超时；
- `TimeoutExpired` 单独处理，随后实际探测目标是否可写；
- 实际可写则继续，不可写则在首个补丁写入前失败；
- 错误返回具体路径、命令阶段和系统信息。

普通本地安装和测试目录不运行 WindowsApps ACL 命令。

## 8. 窗口关闭与任务生命周期

安装或恢复进行中时，`closeEvent` 非阻塞地 `event.ignore()`，显示“操作完成后即可关闭”，不再仅调用无效的 `requestInterruption()` 后退出进程。操作结束后用户可以正常关闭。

本轮不实现用户可取消的事务。若未来增加取消，只能把取消令牌传递到 installer 和补丁模块，并在文件之间的安全点检查；不得中断单个文件原子写操作。

## 9. 检测器中的备份状态

`has_backup()` 改为基于当前 app_dir 的兼容性检查，而不是检查目录是否非空。内部提供明确状态：

- `ready`：匹配当前 install-id、manifest 完整、payload 文件与哈希均有效；
- `missing`：当前安装没有快照；
- `legacy_incompatible`：只有旧扁平备份；
- `mismatch`：快照属于其他安装或版本；
- `corrupt`：manifest、payload 或哈希损坏。

GUI 将这些状态映射为“已准备 / 待生成 / 不兼容 / 已损坏”，不得将旧目录、空目录或陈旧路径显示为“已准备”。

## 10. 缺陷—修复—验证矩阵

| 编号 | 修复 | 核心验证 |
|---|---|---|
| 1 | 删除无条件 zh-CN scrub；只按 manifest 恢复 | 官方原生 `["en-US","id-ID","zh-CN"]` 恢复后字节不变 |
| 2 | install-id + manifest + 哈希预检 | A 快照恢复 A 成功，恢复 B 零写入并拒绝 |
| 3 | 仅恢复 manifest 文件清单 | `patch-state.json` 永不出现在 resources |
| 4 | 增加两个精确 `artifactLabel` 规则 | 英文/旧译名正向修复及反向还原 |
| 5 | installer 最终检测；GUI 统一重检 | 写入成功但检测失败时回滚且不显示已汉化 |
| 6 | 相对 resources 保存完整路径 | v1/v2 同名文件分别精确还原 |
| 7 | manifest 保存配置键存在性与原值 | 缺失、字符串、null、自定义字体均原样恢复 |
| 8 | backup 返回布尔并成为写入门禁 | 模拟复制失败时目标哈希不变、安装失败 |
| 9 | 精确目标权限预检一次 | 无 resources `/r`、`/t`，失败发生于零写入阶段 |
| 10 | 忙碌时拒绝退出 + 原子写 | close 非阻塞但进程继续；replace 失败时原文件完整 |
| 11 | 当前安装专属备份状态 | 空目录、陈旧 app、错版本、缺文件、错哈希均非 ready |
| 五项 | 精确消息 ID + 旧版规则 + 侧栏上下文兜底 | 真实 ID 目录与新版 bundle 夹具得到五项目标文案 |

## 11. 测试与验收

新增集中式恢复安全与事务测试，同时更新现有翻译、补丁、恢复、防卡死和 GUI 测试。至少覆盖：

1. manifest schema、install-id 稳定性与路径安全；
2. 旧备份隔离，不删除旧数据；
3. 安装前备份失败零写入；
4. 安装中写入失败自动回滚；
5. 最终检测失败自动回滚；
6. 恢复预检失败零写入；
7. 恢复中失败回到恢复前状态；
8. 多 assets 目录与同名文件；
9. locale/font 原值矩阵；
10. 原子写异常与临时文件清理；
11. 五项 React-Intl ID、旧版结构及 DOM 上下文规则；
12. `artifactLabel`、防误替换与反向恢复；
13. 权限调用范围、超时与实际可写复核；
14. GUI 安装后重检和忙碌关闭行为；
15. 完整隔离 patch → detect → restore 字节级往返；
16. PyInstaller 正式构建、打包源码一致性、Qt DLL、GUI 冒烟和 SHA-256。

最终验收要求：全部自动化测试通过；旧备份不会自动恢复；五项截图位置显示指定中文；恢复不会删除官方 zh-CN；正式 `dist/CC_Chinese/CC_Chinese.exe` 重新生成并包含已验证源码。

## 12. 发布与迁移

首次运行新版工具时只读取旧备份目录并显示不兼容，不重命名、不移动、不删除。若当前 Claude 已经汉化但不存在匹配的新 manifest，工具不得把当前已修改文件当作官方基线；用户需要先用 Claude 官方修复或重装，再执行汉化。由新版工具在干净安装上创建的首个完整快照，才具备自动恢复资格。
