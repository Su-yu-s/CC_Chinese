# 汉化提速与侧栏五项翻译修复设计

## 背景与证据

当前 Claude `1.37937.1.0` 的主 assets 目录包含 3454 个 JavaScript 文件，约 336 MB。旧 chunk 文件名中的内容哈希已经变化，`patch_assets_tree()` 因此退化为全目录内容搜索。实测 WindowsApps 冷扫描为 60.282 秒，缓存后当前实现约 23 秒；参考项目缓存后为 23.158 秒，两者本质上存在同一瓶颈。

当前运行时映射已经包含 `New / Projects / Artifacts / Scheduled / Customize`，但静态 chunk 映射不完整，并存在把 `label:"项目"` 反向改回 `label:"Projects"` 的冲突规则。结果是左侧菜单仍可能显示英文。

## 目标

1. 同一 Claude 版本重复汉化时不再扫描全部 JS。
2. 已由旧版本 CC_Chinese 汉化的安装可快速升级到新补丁。
3. Claude 更新或补丁内容变化时自动使缓存失效，并由入口静态补丁与 DOM 运行时共同兜底。
4. 左侧菜单稳定显示：`新建 / 项目 / 作品 / 定时 / 定制`。
5. 保持恢复原版、WindowsApps 与本地安装两种路径可用。
6. 不增加第三方运行时依赖。

## 非目标

- 不重写现有汉化资源生成体系。
- 不依赖外部 `rg`、Aho-Corasick 扩展或联网服务。
- 不直接修改用户当前安装；交付物仍由重新打包后的 CC_Chinese 执行汉化。

## 设计

### 1. Chunk 状态缓存

在现有官方备份目录中新增独立的 `chunk-state.json`，避免与 JSON 白名单的 `patch-state.json` 相互覆盖。状态包含：

- schema 版本；
- 规范化 app 路径；
- assets 指纹；
- 补丁签名；
- 上次命中的目标文件相对路径；
- 完成时间和补丁数量。

assets 指纹由所有 JS 的相对路径、大小和纳秒修改时间组成，并在补丁完成后计算。Store 更新会改变 app 路径；本地安装原地更新会改变文件元数据，两种情况都会使缓存失效。

补丁签名由 `PATCHES`、字体运行时、会话运行时以及显式翻译修正规则确定性序列化后计算。代码或文案变化会自动触发重新处理。

状态文件解析失败、字段不完整或文件不存在时按缓存未命中处理。写入采用临时文件加原子替换，避免异常退出留下半截 JSON。

### 2. 三条执行路径

1. **完全命中**：assets 指纹和补丁签名均一致，跳过 `patch_assets_tree()`，只确认字体配置镜像。
2. **旧补丁升级**：没有新状态文件，但所有入口 `index-*.js` 已包含字体和会话运行时标记。仅执行精确/前缀 chunk、刷新入口运行时并写入新状态；不执行合成全局规则的 3454 文件扫描。
3. **首次或更新后安装**：缓存失效且缺少旧运行时标记，仅扫描入口 bundle；未知懒加载 chunk 由 DOM 运行时映射兜底，完成后保存状态。

恢复原版时删除 `chunk-state.json`，保证下次安装不会错误跳过。

### 3. 目标文件发现

目标发现按以下顺序执行：

1. 原始 glob 精确命中；
2. 对 `c71860c77-DNv5VYLZ.js` 这类旧哈希名称提取稳定前缀，尝试 `c71860c77-*.js`；
3. 合成规则或稳定前缀仍无结果时，只扫描 `index-*.js` 入口 bundle，不遍历全部懒加载 chunk。

实测稳定前缀可将设置 chunk 从 3454 个文件缩至 118 个（约 6.9 MB，0.079 秒），导航 chunk 缩至 1 个（0.002 秒）。

入口搜索前先移除 `__CLAUDE_ZH_CN_*_PATCH_BEGIN/END__` 注入块，避免补丁文本命中自身；多条文案通过单次正则完成发现。当前安装只读基准由旧实现约 60.282 秒降为约 4.188 秒，已有补丁升级检查约 0.162 秒，同版本缓存校验约 0.084 秒。

### 4. 五项翻译

静态 chunk 显式支持以下标签：

| 原文 | 最终译文 |
|---|---|
| New | 新建 |
| Projects | 项目 |
| Artifacts | 作品 |
| Scheduled | 定时 |
| Customize | 定制 |

处理规则：

- 添加缺失的精确 `label`/菜单结构替换，不对任意用户文本做全局单词替换；
- 删除 `label:"项目" -> label:"Projects"` 冲突映射；
- 将旧译名 `工件 / 已安排 / 自定义` 在对应菜单标签上下文中规范为 `作品 / 定时 / 定制`；
- 保留 DOM 运行时的五项精确映射，覆盖动态加载界面；
- 路径 `Documents/Claude/Artifacts`、项目名称和非菜单业务文本不得被误改。

### 5. 进度与日志

`patch_assets_tree()` 接受可选进度回调。GUI 在目标发现期间持续显示已扫描文件数，不再从约 68% 长时间直接跳到 95%。最终日志分别记录 JSON、chunk 目标发现、替换和总耗时。

## 错误处理

- 缓存读取失败：忽略缓存并执行安全完整路径。
- 缓存写入失败：汉化结果仍可成功，但日志提示下次可能重新扫描。
- 稳定前缀无候选：回退入口 bundle 静态发现，并由 DOM 运行时覆盖动态界面。
- 目标文件在缓存后消失：缓存失效并重新发现。
- 翻译或运行时写入失败：保持现有 best-effort 权限提示和失败结果。

## 验证方案

1. 翻译夹具包含五个英文标签和三个旧译名，补丁后必须得到指定五项中文。
2. 验证 `Documents/Claude/Artifacts`、用户项目名及非菜单文本保持不变。
3. 前缀发现测试证明旧哈希优先匹配同前缀文件，不读取无关 JS。
4. 首次安装测试执行有界入口发现路径并生成状态。
5. 重复安装测试证明状态命中后不读取 JS 内容。
6. 旧补丁升级测试只更新目标 chunk 和入口运行时。
7. 修改文件元数据或补丁签名后，缓存必须失效。
8. 恢复测试必须还原英文并删除 chunk 状态。
9. 在当前 3454 文件安装上做只读/隔离性能验证，重复路径目标为数秒内完成。
10. 运行现有翻译、补丁、恢复、防卡死和 GUI 冒烟测试，重新构建并验证正式 EXE、资源和 SHA-256。

## 验收标准

- 五项菜单文案与用户指定完全一致。
- 同版本重复汉化不进行全目录 JS 内容扫描。
- Claude 更新、补丁更新和恢复后不会错误命中旧缓存。
- 首次安装由有界静态发现与 DOM 运行时共同保持可见翻译覆盖。
- 所有自动化测试通过，最终 `dist/CC_Chinese/CC_Chinese.exe` 可启动。
