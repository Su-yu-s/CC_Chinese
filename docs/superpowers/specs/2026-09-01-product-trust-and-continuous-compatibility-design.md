# 产品信任与持续兼容设计

## 状态

- 日期：2026-09-01
- 产品：CC_Chinese（用户界面名称调整为“Claude Desktop 中文助手”）
- 用户选择：方案 A——当前版本先完成状态真实性与信任加固，联网更新、后台监控、代码签名和遥测作为后续路线图
- 关联规格：`docs/superpowers/specs/2026-08-31-restore-safety-and-translation-repair-design.md`

## 背景与事实校正

Claude Desktop 更新会替换应用包和资源目录，使既有补丁与备份失效。因此产品提供的真实价值不是执行一次字符串替换，而是让用户能够安全、可验证地维持中文体验，并在版本不兼容时诚实停止。

现有实现的工程能力强于产品闭环：它能定位安装、写入补丁和执行恢复，但更新后的失效感知、兼容性声明、失败求助和用户信任证据仍不完整。当前界面还存在会误导用户的入口：

- “检查更新”只读取本地版本，并不访问真实更新源；
- “更新通道”设置没有接入任何行为；
- 默认以管理员权限启动，即使用户只查看状态也会触发 UAC；
- “汉化前自动备份”允许关闭，与安全恢复的强制快照设计冲突；
- “AppData 网页版”错误描述了本地 Electron 安装；
- 失败只显示短消息，缺少可复制详情和日志入口；
- 安装脚本没有安全恢复协议，直接增加卸载恢复命令会带来跨版本误恢复风险。

以下两项经源码核对后不作为当前缺陷：

- GitHub 地址已经是 `https://github.com/Su-yu-s/CC_Chinese`，不是 `TODO`；
- 反馈地址已经指向该仓库的 Issues。当前版本保留这两个有效入口。

关于修改官方资源可能违反服务条款或导致账号风险，目前没有足够证据支持确定性表述。本产品只披露可验证事实：它是非官方工具，会修改本地应用资源，Claude 更新可能使补丁失效；不写未经核实的账号风险结论。

## 产品原则

1. **状态必须来自事实。** “已汉化”“可恢复”“兼容”只能来自文件、manifest 与补丁结构的验证，不得由按钮执行成功或异常缺失推断。
2. **不确定时零写入。** 未验证的 Claude 版本、来源不明的备份、布局漂移或权限预检失败都必须在首次写入前停止。
3. **普通查看无需管理员权限。** 提权只服务于明确的写操作，并且只覆盖所选目标。
4. **每次修改都有可信后悔药。** 已封存的安全基线是首次写入前置条件，不是可选增强。
5. **不伪装服务能力。** 没有真实更新源时不展示“检查更新”；没有真实证书时不宣称“已签名”；没有监控进程时不暗示会主动提醒。
6. **最少数据原则。** 当前版本不采集、不上传用户数据；日志只记录诊断所需的技术元数据。

## 范围划分

### 当前版本必须落地

1. 删除虚假的更新入口与无效更新通道。
2. 增加基于资源结构的兼容性门禁。
3. 将安全快照设为强制前置条件。
4. 改为按需提权，并允许普通权限查看状态。
5. 统一用户可见产品名称和安装类型术语。
6. 增加失败详情、复制详情和打开本地日志能力。
7. 增加首次使用风险与隐私说明。
8. 将 README 调整为用户优先的下载、兼容、恢复和排障文档。
9. 与恢复安全规格共同完成状态真实性修复、测试和重新打包。

### 本版明确不做

- 不接入尚未设计和验证的联网自更新。
- 不静默下载或替换正在运行的工具。
- 不常驻托盘、不创建计划任务、不在后台自动提权或自动打补丁。
- 不加入匿名或实名遥测。
- 不把尚未获得的 Authenticode 证书当作构建前提。
- 不直接在卸载器中调用现有不安全的旧恢复逻辑。
- 不改变内部 exe 名称、Inno AppId、QSettings 组织名或既有用户数据路径；需要提权的新版安全快照使用受保护存储，旧备份仍留在原位置。

## 1. 真实更新入口

### 当前版本

从主界面移除“检查更新”按钮，从设置页移除“更新通道”。同步删除或停用只读取本地版本却返回“已可用”的伪检查逻辑，避免其他入口误调用。

保留两个真实外部入口：

- “项目主页”打开当前 GitHub 仓库；
- “问题反馈”打开当前 GitHub Issues。

若需要告诉用户如何获取新版，只使用真实话术：“请前往项目主页查看最新发布”，不得显示已经联网验证过的版本号或“当前已是最新”之类结论。

### 验收

- 界面中不存在无网络行为的“检查更新”和无效更新通道；
- 仓库和 Issues 链接可从界面正常打开；
- 代码中没有将本地 Claude 版本冒充工具远端版本的路径。

## 2. 兼容性门禁

### 判定依据

兼容性不使用脆弱的单一版本号白名单，也不因为找到某个 JS 文件就判定兼容。每个支持的资源形态定义一个结构配置档案（compatibility profile），至少包含：

- 预期资源布局与关键目录；
- 必须存在的 React-Intl 消息 ID 或等价稳定锚点；
- 需要修改的 bundle/locale 结构特征；
- mutation plan 允许出现的候选文件集合；
- 每个目标规则的精确命中数或封闭上限；
- 补丁前与补丁后允许出现的值及其组合；
- 会证明布局已漂移的冲突或缺失条件；
- 已在测试夹具或真实版本上验证的 Claude 版本信息，仅作解释和诊断，不单独决定兼容性。

`verified` 要求恰好一个 profile 匹配。额外候选 bundle、重复规则、超出上限的命中、多个 profile 同时匹配，或“锚点仍在但待修改结构已经改变”都判为 `unknown`。mutation plan 必须由 profile 枚举出的封闭目标生成，不能在通过门禁后再扫描出新的写入目标。

在结构兼容之外，安装器还要判定基线状态。profile 的 clean 检查只针对官方资源目标；locale、字体等用户配置允许任意 schema-valid 原值，不因自定义值变成 `partial_or_foreign`，而是在 sealed baseline 中逐值保存并精确恢复。

匹配的 complete manifest 具有最高判定优先级，不得因为当前资源看起来 clean 就创建新基线：

| complete manifest 下的目标状态 | 行为 |
|---|---|
| 全部等于 manifest 原始值 | `restored_with_manifest`：可复用原基线重新汉化，不新建、不覆盖用户配置原值 |
| 全部等于 manifest 补丁后值 | `expected_patched`：幂等显示已汉化或按 manifest 恢复 |
| 每项都是原始/补丁后值但整体混合 | `recovery_incomplete`：只允许继续恢复到全部原始值 |
| 任一值不属于 manifest 允许状态 | `partial_or_foreign`：拒绝汉化和自动覆盖 |

只有不存在匹配 complete manifest 时，才使用以下新基线判定：

| 基线状态 | 判定 | 行为 |
|---|---|---|
| `clean` | 所有官方资源目标均处于 profile 定义的补丁前状态，用户配置均 schema-valid | 可创建新的封存基线 |
| `partial_or_foreign` | 部分汉化、旧工具修改、第三方资源修改，或值组合不在 profile 中 | 拒绝新建快照与汉化 |

结构 `verified` 不等于基线干净。没有匹配 manifest 的已汉化安装即使结构兼容，也必须判为 `partial_or_foreign`，提示用户先使用 Claude 官方修复或重装，绝不能把当前修改结果保存成“官方原件”。

版本判定结果只有三种：

| 状态 | 含义 | 允许行为 |
|---|---|---|
| `verified` | 当前安装完整匹配一个已验证 profile | 仅当基线为 `clean` 或 complete manifest 状态允许复用时进入事务 |
| `unsupported` | 明确匹配已知不支持布局，或关键锚点冲突 | 拒绝汉化，允许查看状态、日志与项目主页 |
| `unknown` | 无法证明兼容，可能是新版本、残缺安装或第三方修改 | 拒绝汉化，提示等待适配或先修复官方安装 |

`unsupported`、`unknown` 与新基线 `partial_or_foreign` 都必须在权限变更、创建快照和修改文件之前返回。这里的“严格零副作用”表示：Claude 文件与配置、ACL、快照树、patch-state、临时文件及本次操作状态均不变；唯一允许的副作用是在工具自己的日志目录追加一条脱敏诊断记录。恢复操作不依赖当前 profile 猜测，而严格遵循恢复安全规格中的匹配 manifest；没有匹配快照仍然拒绝并保持同样的严格零副作用。

### 用户文案

- verified：`已验证兼容 Claude <版本>`；
- unsupported：`此 Claude 版本暂不支持，请前往项目主页查看适配进度`；
- unknown：`无法确认当前安装是否兼容，已停止修改`。

详情中显示检测到的 Claude 版本、资源布局标识、失败的 profile 检查项和日志位置，但不显示用户聊天、项目路径或凭据。

### 验收

- 受支持夹具恰好匹配一个 profile 并得到 `verified`；
- 新增、删除或篡改关键锚点后得到 `unknown/unsupported`；
- 保留锚点但增加候选 bundle、重复规则、改变待修改结构或同时命中多个 profile 时得到 `unknown`；
- 干净安装、自定义 locale/字体、带匹配 manifest 的已汉化/已恢复/混合状态、旧补丁无 manifest、第三方资源修改和部分汉化分别得到预期基线状态；
- 仅伪造版本号不能绕过结构检查；
- 多安装并存时对实际选择的 app_dir 独立判断；
- 所有拒绝场景中，Claude 哈希与 ACL、快照树、patch-state、临时文件和操作状态均不变，只有脱敏日志可增加。

## 3. 强制安全快照

移除设置页的“汉化前自动备份”开关。每次首次修改某个当前安装前都必须存在或创建与该安装严格匹配、payload 已封存且哈希验证通过的基线。此时 manifest 保持 `staging + baseline_sealed=true`；只有补丁与最终检测成功后才提交为 `complete`。

用户不能为了跳过错误而关闭备份。封存失败时安装失败且“零 Claude/配置/ACL 修改”；未封存 staging 应清理，清理失败时可标记 `invalid` 留作诊断，因此不称为严格零副作用。补丁中途或最终检测失败时，只允许使用本次已封存 staging 做内部回滚，不能把它冒充用户可恢复的 complete 快照。旧扁平备份继续保留并显示“不兼容”，永不作为自动恢复来源。本节的具体事务、manifest、版本隔离和恢复规则完全遵循关联的恢复安全规格。

### 验收

- 所有汉化入口都经过同一个快照门禁；
- UI 和配置中不再提供绕过快照的选项；
- 封存成功、补丁失败、最终检测失败和完整成功四条路径具有明确状态迁移；
- 快照失败、错版本或哈希错误时补丁目标字节不变；
- 用户主动恢复只接受 complete，事务内部回滚只接受当前操作的 sealed staging。

## 4. 按需提权

### 运行模型

主程序默认以普通用户权限启动，可执行检测、查看状态、打开链接、查看日志等只读操作。移除 PyInstaller 的 `--uac-admin`。

当前版本继续通过需要管理员授权的 Inno Setup 安装到受保护的 Program Files。安装阶段只弹一次 UAC；主程序本身不再带 `--uac-admin`，因此日常启动仍以普通用户权限运行。

当用户明确执行“汉化”或“恢复”时：

1. 先以普通权限完成目标定位、只读兼容性/manifest 预检和写权限探测；
2. 普通安装路径可写时直接在当前进程执行；
3. 仅当选定的 WindowsApps 目标确实需要权限时，从受保护的 Program Files 安装目录启动同一发行版的受限提权子流程；
4. 如果程序从 dist、下载目录或任何普通用户可写/可重解析位置运行，禁用提权入口，并提示先正式安装；
5. 提权参数只携带枚举动作、安装定位提示和不可预测 nonce，不携带源路径、文件清单或 mutation plan；
6. patch 动作由提权进程从自身受保护安装目录中的内置 profile 重新定位目标、重新生成 mutation plan，并重新校验 install-id、兼容状态、基线状态与所有目标当前哈希；
7. restore 动作不要求当前 profile，独立重新校验 complete manifest、install-id、受保护 payload、当前目标哈希和路径安全，再按 manifest 生成恢复计划；
8. 对 exe 目录、快照根、目标目录和待写文件执行规范化与 reparse-point 拒绝检查；在每次原子替换前再次核对目标哈希，发现 UAC 间隙漂移即停止并回滚；
9. 需要提权的快照由提权进程写入 ProgramData 下仅管理员可修改、普通用户只读的快照树。LocalAppData 中用户可改的 payload 永不用于管理员恢复；
10. 提权过程只修改重新生成的封闭计划中的具体文件，不递归接管 resources；需要临时 ACL 时只在 sealed baseline 后操作并在每条退出路径恢复原 security descriptor；
11. 结果文件只用于展示诊断，使用 nonce 关联且不携带后续写入指令；主界面始终重新检测真实文件状态，不能信任结果文件或退出码宣告成功。

提权协议不得接受任意命令、任意源路径、父进程提供的文件清单或用户可写恢复 payload，避免把助手变成通用管理员写文件入口。

### 安装包

Inno Setup 保持机器级、受保护目录安装和现有 AppId，安装时需要一次管理员授权；删除打包产物的常驻管理员 manifest，使安装后的普通启动不弹 UAC。安装器同时创建受保护 ProgramData 快照根：owner 为 `SYSTEM` 或 `Administrators`，显式 DACL 只允许 `SYSTEM/Administrators` 修改并允许普通用户读取，且禁用会重新开放写权限的不安全继承。覆盖升级继续使用同一 Program Files 目录、卸载记录和快捷方式作用域，避免机器级与每用户安装并存。

每次提权使用前都验证快照根、manifest 和 payload 的 owner、DACL、继承状态及 reparse-point 状态。预先存在的弱 ACL、普通用户可写对象或 reparse 根一律判为 `ELEVATION_TAMPERED`，不得现场“修好后继续”，以免接受攻击者预置内容。

### 验收

- 启动和只读检测不弹 UAC；
- 普通可写安装执行汉化不弹 UAC；
- WindowsApps 写操作最多为该次明确操作弹一次 UAC；
- dist/下载目录中的便携运行禁止提权，但保留只读检测和普通可写目标能力；
- exe、相邻 DLL、动作、目标提示、nonce、manifest/payload 或目标在 UAC 前后被篡改时，提权操作被拒绝且零写入或事务回滚；
- 提权进程不接受父进程生成的 mutation plan，并且只使用受保护的管理员快照；
- ProgramData 根首次安装的 owner/DACL 符合固定模板；弱 ACL、可写 manifest/payload 或 reparse 根均拒绝，不能仅靠内容哈希放行；
- 权限准备部分失败、补丁失败、恢复失败、UAC 间隙漂移和成功完成后，所有临时 owner/DACL/继承/属性均还原；
- 结果返回后 GUI 依据重新检测结果更新，不依据子进程退出码乐观显示成功。

## 5. 名称与术语

用户可见名称统一为“Claude Desktop 中文助手”，包括：

- 窗口标题；
- 主界面产品标题与说明；
- 开始菜单和卸载列表显示名；
- 安装向导标题；
- README 用户标题。

内部兼容标识保持不变：`CC_Chinese.exe` 文件名、Inno AppId、QSettings 标识、备份目录名和日志目录名不迁移。

设置中的“AppData 网页版”改为“AppData 本地安装版”。“WindowsApps 商店版”等其他来源名称以实际安装形态描述，不将 Electron 本地应用称作网页。

### 验收

- 用户可见界面不再使用有歧义的裸 `CC_Chinese` 作为产品标题；
- 升级安装仍识别同一 AppId，原设置和安全快照路径不变；
- 安装来源名称与实际路径含义一致。

## 6. 失败详情与隐私安全日志

### 交互

短提示继续负责告诉用户“发生了什么”，但任何安装、恢复、检测或提权失败都同时生成可展开的详情区域，提供：

- 一句话可执行建议；
- 错误阶段和稳定错误码；
- 检测到的 Claude 版本、安装类型和经过脱敏的目标标识；
- “复制详情”按钮；
- “打开日志目录”按钮；
- “问题反馈”入口。

复制详情使用适合提交 Issue 的纯文本格式，包含工具版本、系统版本、Claude 版本、错误码和关联日志文件名。

当前版本使用有限且稳定的失败阶段与错误码，不把任意异常文本当作分类：

| 阶段 | 稳定错误码 |
|---|---|
| 定位 | `LOCATE_NOT_FOUND`、`LOCATE_AMBIGUOUS` |
| 兼容 | `COMPAT_UNSUPPORTED`、`COMPAT_UNKNOWN`、`COMPAT_AMBIGUOUS`、`BASELINE_DIRTY` |
| 快照 | `SNAPSHOT_CREATE_FAILED`、`SNAPSHOT_INVALID`、`SNAPSHOT_MISMATCH` |
| 权限/提权 | `PERMISSION_DENIED`、`ELEVATION_UNAVAILABLE`、`ELEVATION_CANCELLED`、`ELEVATION_TAMPERED` |
| 汉化 | `PATCH_WRITE_FAILED`、`PATCH_VERIFY_FAILED`、`PATCH_ROLLBACK_FAILED` |
| 恢复 | `RESTORE_NO_MATCH`、`RESTORE_PREFLIGHT_FAILED`、`RESTORE_WRITE_FAILED`、`RESTORE_VERIFY_FAILED`、`RESTORE_ROLLBACK_FAILED` |
| 检测 | `DETECT_FAILED` |

底层异常作为脱敏后的 `cause` 附在稳定错误码后，不能改变 UI 分支或遥测语义。新增错误阶段时必须同步更新测试矩阵和用户排障文档。

### 日志边界

日志允许记录：时间、工具版本、系统版本、Claude 包版本、profile 名称、资源相对路径、替换计数、文件大小、哈希摘要、错误阶段与系统异常。

日志禁止记录：

- 聊天内容、会话标题或提示词；
- 项目/工作区内容；
- 环境变量值、访问令牌、Cookie、凭据；
- locale/bundle 文件全文；
- 用户名和完整用户目录。绝对路径应归一化为安装类型与资源相对路径；无法安全脱敏时不记录该值。

日志存放在用户本地应用数据目录，当前版本不上传。采用最多 5 个文件、每个文件最多 2 MiB 的轮转策略，总占用上限约 10 MiB；超限时只删除最旧日志，不删除快照或补丁状态。

### 验收

- 对上述每个稳定错误码制造失败，均能复制详情并打开关联日志；
- 自动测试向路径和异常中注入用户名、令牌和聊天样本文本，日志中不得出现原文；
- UI 不把完整 traceback 直接暴露为唯一错误说明；
- 日志达到 2 MiB 时轮转，超过 5 个时只淘汰最旧日志，其他用户数据保持不变。

## 7. 首次使用说明

首次运行显示一次简短说明，用户确认后保存本地标记。说明必须使用可验证、不过度恐吓的话术：

> 这是非官方的 Claude Desktop 中文体验工具。汉化会修改本机 Claude 的界面资源，不读取你的对话或工作区。Claude 更新可能使汉化失效；工具只会在确认版本兼容并封存安全基线后修改文件，恢复也只使用与当前安装严格匹配的完整快照。

提供“了解如何恢复”和“查看项目源码”入口。用户拒绝时仍可查看说明和退出，但不执行写操作。版本升级若风险模型发生实质变化，可提升 disclosure 版本并再次展示；纯文案修订不反复打扰。

### 验收

- 新用户执行写操作前必定看到说明；
- 用户未确认时不能汉化或恢复；
- 说明明确非官方、本地资源修改、更新失效、数据边界和安全恢复条件；
- 不出现未经证实的账号封禁或服务条款断言。

## 8. README 与用户支持

README 首屏面向普通用户，按以下顺序组织：

1. 这是什么、当前解决什么问题；
2. 下载哪个文件以及支持的 Windows/Claude 范围；
3. 安装与一键汉化步骤；
4. 工具会修改什么、不会读取什么；
5. Claude 更新后怎么办；
6. 如何安全恢复与卸载助手；
7. 常见问题：不兼容、权限、半汉化、启动异常；
8. 如何复制详情、查找日志和提交 Issue；
9. 开发、构建与贡献说明。

兼容范围由工具代码中的 profile 生成或与其共享单一数据源，不能让 README 手工声明与程序判断长期漂移。

本版卸载行为必须写清：卸载器只移除助手程序、快捷方式和卸载项，不自动恢复 Claude，也不删除 LocalAppData/ProgramData 中的安全快照。用户应先在 GUI 中执行并验证“恢复原样”，再卸载助手；若没有匹配 manifest，则提示通过 Claude 官方修复或重装回到干净状态。交互卸载开始前显示这一说明，允许用户取消并返回助手恢复；静默卸载不猜测恢复，保留快照并按正常卸载结果返回。

当前卸载测试必须证明：不调用旧 restore、不改写 Claude 资源、不删除安全快照，并且交互模式明确提示“卸载助手不等于恢复 Claude”。自动恢复、恢复失败阻止卸载等完整协议仍属于路线图 11.4。

## 9. 当前版本完整用户流程

```text
启动（普通权限）
  → 只读定位 Claude 安装
  → 显示真实汉化/备份/兼容状态
  → 用户点击汉化
      → compatibility profile 预检
      → 基线状态判定
      → 首次使用说明（verified 且未确认时）
      → 写权限探测
          → 可写：创建并验证 sealed staging → 本进程事务执行
          → WindowsApps 不可写：受保护程序按需提权
              → 子进程重新预检并在受保护存储封存基线
      → 补丁后重新检测
          → 通过：manifest 提交为 complete，显示已汉化
          → 失败：使用 sealed staging 自动回滚并显示可复制详情
```

恢复流程不经过兼容 profile 猜测，只接受与当前安装严格匹配的完整 manifest；预检、恢复或恢复后验证失败时必须遵循恢复安全规格的零写入/事务回退规则。

## 10. 发布门槛

本版发布前必须同时满足：

- 恢复安全与翻译可靠性规格的全部自动化测试；
- 本规格中当前版本范围的自动化与 GUI 冒烟测试；
- 不兼容版本零写入测试；
- 普通启动不提权、WindowsApps 写操作按需提权测试；
- Program Files 发行版、便携 dist 禁止提权、UAC 间隙篡改与受保护快照测试；
- 全错误码详情、日志脱敏与 10 MiB 轮转上限测试；
- 新安装、同一机器级安装覆盖升级、取消与失败回滚测试；
- 当前卸载只移除助手、不恢复 Claude 且保留快照测试；
- 正式 exe 与安装包从已提交源码重新生成；
- 发布产物计算并公布 SHA-256；
- 在没有真实证书时明确标注“未进行代码签名”，不伪造发布者身份。

## 11. 后续路线图

### 11.1 真实更新检查

后续单独设计并接入 GitHub Releases：

1. 第一阶段只检查并提示，用户主动打开发布页下载；
2. 对 release 元数据做超时、TLS、限流和失败降级处理；
3. 下载能力若后续加入，必须校验发布资产 SHA-256，并在替换前展示版本和来源；
4. 不在运行中静默自替换，也不把网络失败解释为“已是最新”。

### 11.2 失效感知与监控

先提供可选的启动时版本检查；证明可靠后，再考虑用户明确选择的托盘或计划任务监控。后台监控只检测 Claude 版本/补丁状态并通知，不自动申请管理员权限、不静默重打补丁。任何常驻能力都要有清晰开关、资源占用说明和卸载清理规则。

### 11.3 代码签名与发布身份

获得真实 Authenticode 证书后，将 exe 和安装包签名纳入不可跳过的发布流水线，并在发布页同时提供 SHA-256。证书主体、时间戳和验签步骤需要写入用户文档。在此之前诚实说明未签名，不能用自签名证书制造虚假信任。

### 11.4 安全卸载协议

卸载恢复必须在事务恢复成熟后单独实现：

1. 卸载前调用专用、稳定的静默恢复命令；
2. 只使用与当前安装严格匹配的完整 manifest；
3. manifest 缺失、错版本或恢复失败时停止并提示，不自动猜测；
4. 交互卸载提供“仅卸载助手、保留当前 Claude 状态”的明确选项；
5. 静默卸载在不能安全恢复时返回非零退出码；
6. 默认保留安全快照，除非用户在独立步骤明确确认删除。

当前版本不添加 `[UninstallRun]` 调用旧恢复函数，因为那会把现有恢复缺陷引入卸载路径；当前透明但非自动的卸载行为见第 8 节。

### 11.5 遥测与隐私

当前默认零遥测。未来若需要成功率或版本分布，必须先写独立隐私规格并仅采用显式 opt-in。最小候选字段为随机安装标识、工具版本、Claude 版本、profile、结果码和耗时；不得包含路径、设备账户、IP 的持久标识、聊天或项目数据。必须提供查看样例 payload、随时关闭和删除标识的能力。

### 11.6 翻译风格与第二曲线

建立翻译风格约定，至少定义语气、术语表、菜单/按钮长度、一致性和专有名词保留规则。长期定位可由单次“汉化工具”逐步演进为“Claude Desktop 中文体验增强”，但字体、会话管理等新功能必须各自经过需求验证，不能削弱安全恢复这一核心能力。

## 12. 决策记录

| 决策 | 选择 | 原因 |
|---|---|---|
| 本版范围 | 真实性与信任加固 | 先修复会误导或伤害用户的现有闭环 |
| 更新按钮 | 当前移除 | 没有真实远端数据就不能宣称检查更新 |
| 兼容判定 | 唯一结构 profile + 封闭 mutation plan | 比单一版本号、文件名或最小命中更能发现布局漂移 |
| 未知版本 | 拒绝写入 | 新版本上错误补丁的代价高于等待适配 |
| 备份 | 写入前 sealed staging，验证后 complete | 同时满足事务回滚与用户恢复的不同可信条件 |
| 权限 | Program Files 保护安装、普通启动、按需提权 | 防止用户可写未签名程序在 UAC 前被替换 |
| 名称 | 用户可见名称调整，内部标识保持 | 减少歧义且不破坏升级兼容性 |
| 日志 | 本地、脱敏、零上传 | 提供求助证据同时保护用户数据 |
| 当前卸载 | 只卸载助手并明确提示 | 不把旧恢复漏洞偷渡进卸载路径 |
| 自动卸载恢复 | 后续专用协议 | 需要匹配 manifest、失败阻断和静默语义 |
| 遥测 | 当前不做 | 没有独立同意与隐私设计前不收集数据 |

## 13. 规格完成定义

本规格不是以“界面上增加文案”完成，而是以以下事实成立为准：

1. 用户能在普通权限下看到真实状态；
2. 未验证版本不会被修改；
3. 每次修改前都有与当前安装匹配且已封存的安全基线，成功后才形成 complete 快照；
4. 成功状态来自补丁后检测，失败有可复制且脱敏的证据；
5. 当前产品不再展示没有真实实现的更新能力；
6. 安装包、README 和界面用一致、无歧义的产品表述；
7. 所有当前版本门槛通过后才重新编译并交付安装包。
